# Daftar Risiko Awal dan Penanganan (Initial Risk Register)

### Proses Bisnis: Pembelian (Purchasing) - AdventureWorks

Berikut adalah daftar risiko awal beserta tingkat risiko dan rencana mitigasi/penanganannya untuk proyek data/analytics pada skema pembelian:

| No | Kategori Risiko | Deskripsi Risiko | Tingkat Risiko | Rencana Penanganan / Mitigasi |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Kualitas & Integritas Data** | Adanya nilai kosong (*null*), data tidak konsisten pada status transaksi, atau anomali perhitungan kuantitas barang (`ReceivedQty` vs `StockedQty`) dari database OLTP operasional. | **Tinggi** | • Menerapkan aturan validasi dan *data cleansing* pada pipeline ETL/ELT.<br>• Menyusun *data reconciliation report* berkala untuk mencocokkan total agregat OLTP dan Data Warehouse.<br>• Memberikan penanganan default untuk nilai *null* atau data yang cacat. |
| **2** | **Performa Query & Pemuatan Data** | Ekstraksi data transaksional skala besar dari tabel `PurchaseOrderDetail` memicu *resource spike* dan memperlambat kinerja server database operasional. | **Sedang** | • Menggunakan metode *Incremental Loading* (hanya mengambil data baru/terbaru berdasarkan `ModifiedDate`).<br>• Menjadwalkan eksekusi ETL pada jam di luar jam operasional utama (*off-peak hours*).<br>• Membaca data dari server *read-replica* atau *database backup*, bukan langsung dari server produksi operasional. |
| **3** | **Ketidaksesuaian Definisi Metrik Bisnis** | Perbedaan pemahaman antara tim bisnis (*Purchasing*) dan tim teknis/data terkait definisi kalkulasi metrik (misalnya: formula *Rejection Rate* atau cakupan *Total Spend*). | **Tinggi** | • Menyusun *Business Glossary* dan *Data Dictionary* terstandarisasi sebelum tahap pembuatan dashboard.<br>• Melakukan sesi validasi dan penandatanganan (*sign-off*) definisi metrik bersama *stakeholder* bisnis. |
| **4** | **Perubahan Skema Database Operasional** | Perubahan nama kolom atau penambahan/pengurangan tabel pada skema `Purchasing` operasional yang menyebabkan pipeline ETL gagal (*error/break*). | **Sedang** | • Menerapkan mekanisme *logging* dan *alerting* otomatis jika pipeline data mengalami kegagalan.<br>• Menyusun SOP *Change Management* antara tim Database Administrator (DBA) dan Data Engineer.<br>• Menggunakan skrip ETL berbasis *version control* (Git). |
| **5** | **Keamanan & Kerahasiaan Data** | Akses yang tidak terotorisasi terhadap informasi harga beli (`UnitPrice`), total nilai transaksi pembelian, atau data kerahasiaan vendor. | **Tinggi** | • Menerapkan *Role-Based Access Control* (RBAC) pada server Data Warehouse maupun platform BI.<br>• Mengatur kerahasiaan tingkat kolom (*Column-Level Security*) untuk membatasi visibilitas data sensitif.<br>• Menerapkan enkripsi data saat transit (*in-transit*) maupun saat tersimpan (*at-rest*). |
